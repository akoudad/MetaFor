# Chat integration

The desktop renderer bundles the existing React and Three.js conversation view. It does not load a hosted website. The web checkout is unchanged.

- A narrow fetch adapter routes `/api/status` and `/api/answer` to the main process. Model keys stay outside the renderer. Cancelling a question also cancels native provider work.
- Chat keeps the existing `.ingx` schema, local history, topic graph, reading positions, and annotation drafts. Browser conversations can be moved through **Open .ingx**; browser profiles are not read automatically.
- Native file imports receive a fresh conversation ID before reaching Chat, including files exported from Help. This preserves the imported graph without attaching a crop by a coincidentally matching ID. Only internal **Continue in Chat** preserves the Help identity and source link.
- **Continue in Chat** converts a Help exchange into a validated `.ingx` snapshot. Its conversation ID remains the Help session ID, linking it to the original captured source in the private desktop store.
- Chat cards contain the original questions and answers. Exact source metadata and visual marks remain in native Help storage and **Shared source**, rather than appearing as UUIDs or coordinate JSON in the transcript. The writer receives relevant frames, exact marks for anchored turns and their paired question/reply, and marks from the last 16 imported turns on those frames. The prompt asks for ordinary language and human-readable application/window names.
- The current Chat is saved before a Help exchange opens. Reopening the same Help exchange adds unseen messages and preserves branches, drafts, and reading positions already created in Chat. Earlier generated metadata sections are removed only when they exactly match the native archive and no branch or annotation refers to them. Edited sections are kept. An unavailable archive leaves those sections intact and still imports the valid transcript. Changed question/answer text causes a visible error instead of overwriting saved work.
- **Shared source** opens saved images, application/window names, and capture times beside Chat. Each turn retains its source identity so old annotations remain attached to their original image after a screen refresh. Sources are still images, not a live video stream.
- Chat follows selected passages and nested topic references back to their original native frame, using stable message IDs instead of editable source text. Multiple annotated passages can supply separate labeled frames (at most three images, with an 8 MiB secondary-image budget); omitted images are explicitly identified to the model. The collapsed source control states that follow-ups use saved screen context. Source state refreshes when Chat regains focus, becomes visible, or receives a Help update. A deleted source disappears and the chat explicitly continues with text only. Visual marks use the source image's aspect ratio, including arrows with signed offsets.
- New `.ingx` exports contain readable transcript text and stable message IDs. Native image attachments, capture metadata, and visual marks stay in the desktop Help store and are available to internal Chat follow-ups; they are not embedded in the exported file.

`desktop/tests/chat-transfer.test.ts` covers provenance, valid exports, repeat imports, branch/draft preservation, and changed-message rejection. `desktop/tests/chat-fetch.test.ts` covers API isolation, cancellation, and error propagation. `desktop/tests/chat-ui.test.tsx` verifies draft preservation, waiting for an active answer before opening Help, malformed-import recovery, and model-status refresh. The existing UI tests continue to exercise scrolling, branching, and text annotations.

`desktop/tests/shared-source-ui.test.tsx` covers deleted/unreadable source recovery, preserving an open panel during refresh, saved-context disclosure, annotation geometry, and stale lookups after a conversation switch.

Help ignores its initial session lookup if a newer session event has already arrived. `desktop/tests/help-ui.test.tsx` verifies that a new capture and its draft survive that delayed response, and that unreadable history entries do not block healthy exchanges.

Help model requests include the current frame and at most two earlier frames referenced by the last 16 messages, with an 8 MiB budget for prior images. Historical marks are labeled by source; only marks on the current question source can be highlighted. The model may create up to six validated visual pointers or translation anchors on that source, with at most 12 total highlights and new marks. It can explain which action the user could take but cannot execute actions. The complete saved exchange remains limited to 16 MiB and 64 distinct sources; exceeding either limit reports an error rather than discarding old frames.
